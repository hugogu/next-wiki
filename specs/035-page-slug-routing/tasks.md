# Tasks: Page Slug Routing

**Input**: Design documents from `/specs/035-page-slug-routing/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/page-address-api.md](./contracts/page-address-api.md)

**Tests**: Included. This feature touches permissions, import/export, and the
public API, all three of which the constitution's Compliance Review requires
tests or manual verification notes for, and `quickstart.md` enumerates the
required coverage.

**Organization**: Grouped by user story so each can be implemented, tested, and
shipped independently.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1–US5)
- Exact file paths are given in every task

## Implementation Strategy

### MVP First (User Story 1 only)

1. Phase 1 Setup
2. Phase 2 Foundational — **critical**, blocks everything
3. Phase 3 US1
4. **STOP and VALIDATE**: publish, move across the tree, confirm the URL never
   moved; confirm the backfill drift check reports zero
5. Shippable. Legacy redirect mechanisms still work untouched, so nothing
   regresses if you stop here.

### Incremental Delivery

1. Setup + Foundational → namespace exists and is DB-enforced
2. + US1 → URLs decoupled from the tree (**MVP**)
3. + US2 → renames safe, one alias mechanism instead of two
4. + US3 → collisions and reserved words rejected with actionable messages
5. + US4 → multiple addresses per page, manageable in the UI
6. + US5 → Wiki.js and archive migration preserve every inbound link
7. Polish → mandate amendment, docs, cleanup, full validation

### Parallel Team Strategy

Everyone lands Setup + Foundational together (one person owns the migration
tasks — see the serialization warning). Then: developer A takes US1 (largest,
on the critical path), developer B takes US3 once US1's write paths settle,
developer C takes US5. US2 and US4 follow US1.

## Notes

- `[P]` means different files and no dependency on an incomplete task
- Never hand-author a migration `.sql` or edit `meta/_journal.json` /
  `meta/NNNN_snapshot.json`; only the backfill in T007 is appended to an
